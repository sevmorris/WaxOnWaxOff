### You no longer have to wait out verification

After WaxOff writes your files it re-measures them, and every row reads Complete while that happens. On a batch of hour-long files that is over a minute where the app looked busy, the toolbar offered to cancel work that was already on disk, and you could not start anything else.

Two changes. The toolbar now says what it is actually doing — "Verifying delivered files… N done" — with a Cancel scoped to the verification rather than the delivery. And you can start the next batch during that window: doing so ends the outstanding verification, which costs nothing, because the files it was measuring are already written.

Starting a new batch is still refused while a batch is genuinely delivering. That restart would throw away renders in progress, which is a different bargain entirely.

### WaxOn tells you which normalization it applied

`loudnorm` treats linear normalization as a request it can refuse. WaxOff has reported the outcome since 2.5.0; WaxOn now does too, in the Console at Verbose. WaxOn's wider loudness-range setting makes the fallback far less likely — but not impossible, and now you can see it rather than infer it.

### Platform loudness targets, corrected and sourced

The delivery-targets table in the Theory of Operation carried figures behind an undated hedge. Every one is now cited to the platform's own documentation or the governing specification, and several were wrong: Buzzsprout targets two levels rather than one, Apple's −16 LKFS is advice to authors rather than playback normalization, Spotify's −14 LUFS is its music figure with none published for podcasts, and YouTube publishes no loudness target at all — so the number everyone quotes for it is now marked unconfirmed rather than repeated.

### A licensing note

The FFmpeg binaries bundled through v2.3.0 have been withdrawn from distribution. They came from a third-party GPL build whose exact Corresponding Source could not be obtained, so the obligations that came with distributing it could not be met. Anyone who already has those builds keeps the rights the GPL granted them. Builds from 2.4.0 onward are unaffected — they use an audio-only LGPL FFmpeg built from a recipe in this repository.

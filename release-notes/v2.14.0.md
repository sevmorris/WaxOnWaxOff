**Changed**
- **WaxOff accepts mono or stereo sources only.** A file with more than two channels now fails with an error in its row, and the rest of the batch continues. Before, WaxOff processed such a file and folded it down to stereo after the limiter, so the delivered file was far below the target loudness. The manual, the theory page and the in-app Help now give the limit.

**Fixed**
- **Cancel followed quickly by Process no longer loses the new batch.** In WaxOn and WaxOff, Process takes the place of Cancel, so a double-click on Cancel started a new batch while the cancelled one was still stopping. When the cancelled batch stopped, it reset the state of the new one: the new batch continued, but the toolbar showed Process and there was no Cancel to stop it. Now each batch changes only its own state.
- **A cancelled or failed WaxOff render no longer leaves a temporary WAV file.** FFmpeg keeps what it wrote before it stopped. That partial file, up to the size of the delivered WAV, stayed in the app's temporary folder until you quit the app. Now WaxOff deletes it.
- **WaxOff's disk-space check now counts the files that it processes at the same time.** WaxOff delivers many files at once, and each one writes its own temporary WAV. The check counted only one, so it could accept a batch that then filled the startup disk. It also counts a mono source at stereo size, because WaxOff writes a stereo temporary file for it.
- **A failed save no longer deletes the existing output file.** When a file with the same name was already there, WaxOn and WaxOff deleted it before they moved the new file into place. If the move then failed, for example on a full external disk, neither file was left. Now the new file replaces the old one in one step, and a failure leaves the old file as it was.

**Interface**
- **The "ISP (est.)" statistic is gone.** The stats panel showed it only when its inter-sample peak estimate was above the sample peak. The estimate was the midpoint of two adjacent samples, which can never be above the higher of the two, so the statistic never showed. The README, the manual and the theory page no longer list it.

**Developer**
- `release.sh` releases only from `main`. It stops unless the branch you are on and the branch it pushes to are both `main`. Before, a release from a work branch passed every check, because the pull request for that branch had green CI for the same commit.

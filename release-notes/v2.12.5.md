**Changed**
- **The bundled FFmpeg is 8.0.3**, the third point release on the 8.0 branch, up from 8.0. It carries about 500 fixes, many of them hardening the file readers every input goes through — MOV/MP4, Matroska, WAV and AAC — against overflows, out-of-bounds reads and use-after-frees on malformed files. Processing is unchanged: run through the app's actual WaxOn and WaxOff chains, the new build's output is bit-identical to the old one's (221 parity gates pass, every null residual at −inf, every loudness and true-peak delta 0.0000), and MP3 exports decode to identical audio — the file differs only in the encoder string in its ID3 tag. The source verified against FFmpeg's release signing key, the licence files are unchanged, and the build is still this repo's own reproducible, LGPL, audio-only recipe (`ffmpeg-deps-8.0.3-audio-arm64-r4`).

**Fixed**
- **The app keeps its notarization once it is out of the disk image.** Only the DMG was stapled, so the copy dragged into Applications — the only one anyone runs — carried no ticket of its own, and Gatekeeper had to ask Apple about it on first launch, which needs a working network. The app is now notarized and stapled by itself before the image is built around it, and the release checks the ticket on the copy that ships.
- **The disk image is signed.** Only the app inside it was, so `spctl` reported the download itself as having "no usable signature" even with a valid ticket stapled to it.

**Developer**
- CI runs the tests on macOS 26 as well as 15, and runs the bundled FFmpeg on macOS 14, the deployment target. Until now it only ever ran on macOS 15, which is how the r2 binaries shipped green while aborting at launch on macOS 26.7.
- `release.sh` no longer bumps the Homebrew cask, which is deprecated — the app updates itself from GitHub — and an interrupted release no longer leaves its version bump in the working tree.

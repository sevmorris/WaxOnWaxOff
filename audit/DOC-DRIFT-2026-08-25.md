## 3. Findings

### WRONG — claims the code contradicts

**F-W1 · `README.md:50`** — "Optional **two-pass** EBU R128 linear gain".
WaxOn has not used two-pass loudnorm since v2.9.0. `AudioProcessor.swift:364` measures once with `ebur128=peak=true:metadata=1` and applies one constant gain (`:249`, `gainDB = target - r.integrated`). The manual states this correctly at `:674` ("WaxOn measures integrated loudness once, then applies one constant gain").

**F-W2 · `README.md:52`** — "**2× oversampled** limiting when Loudness Norm is on".
WaxOn does not oversample. Its chain is `volume=…dB,alimiter=…` with no resampling (`AudioProcessor.swift:262-263`). WaxOff is the mode that oversamples, bracketing its limiter with `aresample` to 2× and back (`DeliveryProcessor.swift:689-692`). The claim appears to have been imported from WaxOff.

**F-W3 · `README.md:52` and `README.md:34`** — "**True peak** held to a fixed −1.0 **dBTP** ceiling".
True only of the Loudness-Norm-**off** path, which measures true peak and attenuates (`AudioProcessor.swift:268`). With Loudness Norm **on**, `alimiter` holds **sample** peaks at −1.0 **dBFS** — the ceiling is derived by `limiterCeilingAmplitude(dBFS: -1.0)` and the app's own log line says `ceiling −1.0 dBFS` (`:261`). Stating one figure for both paths is wrong for whichever path is not being described.

**F-W4 · `docs/index.html:511`** — "**Two-pass** EBU R128 loudness normalization — optional (default off)". Same defect as F-W1.

**F-W5 · `docs/index.html:512`** — "**True peak limiting** — fixed −1.0 dBTP". Same defect as F-W3.

**F-W6 · `docs/index.html:506`** — "always-on **true-peak** limiting" in the Ingest Prep summary. Same conflation; also "always-on" is loose, since the off path applies gain without limiting at all.

**F-W7 · `docs/manual/theory.html:463`** — "**Both modes** are built on the same core DSP stages — EBU R128 loudness measurement, **two-pass linear normalization**, and true-peak ceiling enforcement".
Only WaxOff is two-pass. This survived the 2.9.0 sweep that corrected the rest of the file, and it now contradicts the same document's own pipeline caption 27 lines later at `:490`.

### MISSING — user-visible behavior no document mentions

**F-M1 · `README.md`, section II (WaxOff — Broadcast Delivery)** — no mention of podcast metadata. The headline feature of 2.12.0 (podcast name, episode title, artwork, chapters as ID3v2.3 `TALB`/`TIT2`/`APIC`/`CHAP`/`CTOC`) is absent from the feature list where it belongs. The single "Metadata" string in the README (`:89`, "Metadata Stats: RMS, Peak, ISP…") refers to audio statistics and is unrelated.

**F-M2 · `docs/index.html:517-527` (Delivery & Mastering)** — same omission on the landing page. Its five WaxOff bullets stop at preset recall.

**F-M3 · `README.md` and `docs/index.html`** — neither mentions the file-list bar or the `+` button. Lower stakes than F-M1/F-M2, but the landing page's Ingest Prep summary still implies dragging is the only way in.

### CODE-COMMENT

**F-C1 · `WaxOnWaxOff/Services/AudioProcessor.swift:99`** — "WaxOn ceiling is fixed at -1.0 **dBTP**", two lines above a call to `limiterCeilingAmplitude(**dBFS**: -1.0)` and 160 lines above a log line that says `dBFS`. The same unit conflation as F-W3, inside the code that proves the prose wrong.

## 4. Recommendation

F-W1 through F-W7 are the priority: they are wrong about what the app does to audio, on the two documents a new user reads first, and they have been wrong since 2026-08-19. The fix is small — borrow theory.html's `:490` wording, which is already correct and already reviewed.

F-M1 and F-M2 are worth the same pass. A feature that shipped as the headline of a minor release should not require reading the manual to discover.

F-C1 is a one-line comment fix, best done alongside F-W3 so the code and the prose stop disagreeing.

**Root-cause note for next time:** the 2.9.0 correction had the right content and the wrong scope. `README.md` and `docs/index.html` were not in its file list and nothing caught that. Any future correction to a behavioral claim should sweep all five surfaces — README, landing, manual, theory, Help — not only the ones where the claim was first noticed.

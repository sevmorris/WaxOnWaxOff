WaxOn/WaxOff

Podcast audio utility for macOS. Signal conditioning for ingest and broadcast normalization for delivery.

WaxOn prepares raw recordings for ingest. WaxOff finalizes your mixed audio for distribution. Both share the same drag-and-drop workflow, waveform viewer, and file stats panel.

Getting Started

System Requirements

  • macOS 14.0 (Sonoma) or later
  • Apple Silicon Mac (M-series, arm64)
  • FFmpeg is included in the app. You do not install it separately.

Installation

  1. Download the DMG file from the link above.
  2. Open the DMG file.
  3. Drag WaxOn/WaxOff to your Applications folder.

First Launch: Mode Picker

A mode picker appears when you start the app for the first time. Choose WaxOn to prepare your raw recordings. Choose WaxOff to complete a mix. The app then remembers your last mode and opens in that mode. You can change the mode at any time with the WaxOn | WaxOff control in the toolbar. Each mode keeps its own file list. A change of mode does not disturb your work in the other mode.

Updates

WaxOn/WaxOff looks for updates when it starts. It tells you when a new version is available. You can also look for updates at any time. Select Help → Check for Updates…

The Interface

Both modes share the same window layout, divided into four areas.

Toolbar

The top bar contains the mode switcher (WaxOn | WaxOff) on the left. The Preset picker is next to it. The action buttons (Process, Remove, Clear) are after the Preset picker. When a batch runs, the Process button becomes Cancel. The settings-sidebar toggle is at the far right of the toolbar.

File List

The left panel shows all the loaded files. Each row shows the filename and a status label. Drag a row to change its position. Drag the vertical divider to change the size of the panel. You can also drag a folder onto the list. The app scans the folder and its subfolders for supported audio files.

  • Waiting — the file is in the queue and the analysis is not complete
  • Calculating stats — the app computes the audio stats
  • RMS … dBFS · Peak … dBFS — the analysis is complete and the file is ready
  • Processing — the pipeline runs and a progress bar shows below the row
  • Output: … — the file is processed. A green ✓ Complete indicator shows next to the filename. Click the folder icon to show the output file in the Finder
  • Error — the process failed and the message shows in the row

In WaxOn, a file with a high estimated noise floor shows an orange warning triangle next to the filename. Put the pointer on the badge to see the detail. WaxOn also shows a badge for a channel conversion. A stereo source with Channels set to Mono shows a STEREO→MONO L or STEREO→MONO R badge. A source with more than two channels shows MULTI→MONO. In WaxOff, a mono source shows a MONO badge. By default WaxOff upmixes the file to dual-mono stereo before it processes the audio. If you select Mono delivery, WaxOff does not upmix the file.

An advisory banner shows above the list when two or more files are in the WaxOn queue and Phase Rotation is on. If you recorded the files at the same time in the same room, apply phase rotation once at the mix bus instead of once for each track. Refer to Phase Rotation in the Theory of Operation.

WaxOn processes more than one file at the same time. The number of files depends on the available CPU cores. A file that waits its turn shows a muted static progress bar. This shows that the file is in the queue and is not stalled.

To remove files, select them and press Delete. To clear the full list, press ⌘⌥Delete.

Waveform Panel

The right panel shows different content in different conditions:

  • File selected — the panel shows the waveform with a stats strip below it
  • Nothing selected — the panel shows a prompt to select a file

A toggle button in the top-right corner changes between the waveform view and the Console. The Console is a scrollable log. It shows what WaxOn does during processing. The Verbose checkbox shows more detail, such as the filter parameters and the loudnorm measurements for each file. The app keeps the Verbose setting after you restart it.

Settings Sidebar

A collapsible panel on the right edge of the window holds the output format settings for the current mode. These are the sample rate, the channels, and the output directory. To open or close the panel, click the sliders icon at the far right of the toolbar.

Processor Strip

The bar across the bottom of the window holds all the processing controls for the current mode. In WaxOn these are high-pass, phase rotation, Dynamic Leveling, and loudness normalization. In WaxOff these are true peak and target loudness. A toggle shows orange when it is on. To adjust a knob, drag it vertically, use the scroll wheel, or press the arrow keys when the knob has focus. A knob moves in discrete steps. Most controls show a short helper line below them. Every control has a tooltip. The app keeps all the values between sessions, and a preset records them.

WaxOn Mode WaxOn

WaxOn prepares raw podcast recordings for editing in a DAW. WaxOn does high-pass filtering, optional Dynamic Leveling, loudness normalization, phase rotation, and true-peak ceiling control. The output is 24-bit WAV files for Logic Pro, Reaper, or a different editor.

WaxOn is a first-step ingest processor. It puts your raw recordings into a consistent format before you edit them. WaxOn does not do spectral repair, noise reduction, or multiband restoration. For a recording with noise problems, de-essing needs, or other surgical work, use a dedicated tool such as iZotope RX.

Quick Start

  1. Click WaxOn in the toolbar. As an alternative, select WaxOn in the mode picker.
  2. Select a preset from the Preset menu in the toolbar. As an alternative, set the controls in the processor strip and the Settings sidebar.
  3. Drag your audio files onto the window.
  4. Click Process.

Channels Mono · Stereo Stereo sends the two channels of a stereo source through with no change. For a different channel count, FFmpeg converts the source to two channels with its default matrix. WaxOn writes a warning to the console. Mono extracts one channel from a stereo source.

Use Left for a standard single-mic recording on channel 1. The control is not available when Channels is Stereo.

Dynamic Leveling On · Off · default Off This is bidirectional dynamic normalization. Use it for panel recordings, live Q&As, and multi-guest sources with inconsistent voice levels. This prevents broadband noise from changing the loudness measurement. RNNoise has no effect on the output signal. Leveling strength

A low setting uses longer analysis frames and a smaller maximum gain of approximately +6 dB. The result is smoother and more conservative. A high setting uses shorter frames and a larger maximum gain of approximately +15.6 dB. The result is faster and more aggressive. Listen to the output before you edit it.

WaxOn Processing Pipeline WaxOn

Every file goes through an FFmpeg processing chain. The chain has three required stages and a maximum of four optional stages.

  1. Filter, Channel & Resample One high-pass filter operates at max(cutoff, 20 Hz). Thus a 20 Hz floor stays even when HPF is Off, and WaxOn always removes the DC offset. Channel selection is next if you select Mono output. An optional 200 Hz allpass filter for phase rotation follows. It reduces the peak asymmetry and gives the limiter more headroom. The default is on. WaxOn then resamples the audio to the target rate. The output of this stage is a 24-bit PCM WAV file at the target sample rate.
  2. Dynamic Leveling Optional This stage is bidirectional dynamic normalization. It uses the FFmpeg dynaudnorm filter. It increases the level of quiet voices and decreases the level of loud voices. The Strength knob sets three dynaudnorm parameters at the same time: the frame size (f 500→150 ms), the Gaussian smoothing window (g 31→15 frames), and the maximum gain factor (m 2.0→6.0, approximately +6 to +15.6 dB). Use this stage for panel recordings, live Q&As, and multi-voice sources with inconsistent levels. Do not use it for a solo voice: it can cause pumping on a recording with natural pauses. Refer to Dynamic Leveling in the Theory of Operation.
  3. Loudness Normalization Optional This stage is EBU R128 normalization in two passes. The first pass measures the integrated loudness, the true peak, the LRA, and the threshold. The second pass applies a linear gain to reach the configured target. Linear mode keeps the natural dynamic shape of the recording. There is no compression and no change to the transients. If the true-peak headroom does not permit a constant gain, loudnorm applies dynamic normalization for that file instead. The analysis pass runs RNNoise on a temporary copy. Thus broadband noise does not increase the LUFS reading. RNNoise has no effect on the output pipeline. Refer to the Theory of Operation.
  4. True-Peak Control When Loudness Norm is on, WaxOn upsamples the signal to 2× the target rate. The signal then goes through the FFmpeg alimiter filter with a 5 ms attack and a 50 ms release. WaxOn then resamples the signal back. The 2× rate makes the inter-sample peaks visible to the limiter. Thus the limiter prevents true-peak violations. When Loudness Norm is off, WaxOn uses downward-only linear peak normalization instead of the limiter. WaxOn measures the true peak and applies one attenuating gain to bring it to the −1.0 dBTP ceiling. If the source is already below the ceiling, this stage makes no change to the audio. The dynamics of the source do not change. In both conditions the output stays below the −1.0 dBTP ceiling. WaxOn writes it as a 24-bit WAV file.

Output Format

All WaxOn output files are 24-bit WAV. The input format has no effect on this. The format is lossless and uncompressed. It is compatible with every DAW.

WaxOn Output Files WaxOn

Individual Files

{original-name}-{rate}waxon.wav

Examples: episode-01-44kwaxon.wav   guest-48kwaxon.wav

Two files in the same batch can produce the same output name. WaxOn then adds a short hash tag before the type suffix, for example episode-a1b2c3-44kwaxon.wav. Thus one file does not overwrite the other.

A file with a name that already agrees with this pattern shows an Already Processed? confirmation when you add it. If you process a prep WAV file again, the audio quality can decrease.

Location

By default, WaxOn writes the output files to the folder of the source file. If you set a custom output directory, WaxOn writes all the files to that directory. If it cannot write to either location, WaxOn uses ~/Music/WaxOnWaxOff/ instead. If it cannot create or write to that folder, WaxOn uses the Desktop as the last choice. WaxOn asks you to confirm this if more than one file in the batch goes there. WaxOn overwrites an existing file with the same name.

WaxOff Mode WaxOff

WaxOff finalizes your edited podcast mix for distribution. It applies phase rotation (200 Hz allpass) for headroom recovery, EBU R128 loudness normalization, and a 2× oversampled brick-wall limiter as a true-peak safety backstop. It delivers 24-bit WAV, MP3, or both, ready to upload to your podcast host.

WaxOff assumes your mix is already balanced and edited. It normally applies a single linear gain adjustment from loudnorm to hit the target loudness — no compression, no changes to stereo image. If the loudness range of the mix is more than the internal setting of 9 LU, loudnorm applies dynamic normalization instead. The delivered file is then below the target. Phase rotation is applied unconditionally as a transparent crest-factor reduction. The brick-wall limiter only engages when inter-sample peaks slip past loudnorm's TP analysis; on a well-mixed source it leaves the audio untouched. See the Theory of Operation for detail. If your mix sounds right, WaxOff just makes it loud enough and packages it for delivery.

Target loudness

−18 LUFS is a safe, conservative target. It is below the levels of the major platforms: Spotify uses −14 LUFS and Apple Podcasts uses −16 LUFS. Thus these platforms increase the level of your file and do not decrease it. A value of −16 LUFS gives a louder result.

WaxOff Processing Pipeline WaxOff

WaxOff uses the FFmpeg loudnorm filter in a pipeline of two passes. This is the only correct way to apply EBU R128 linear normalization.

  1. Analysis Pass A 200 Hz allpass filter for phase rotation goes before the FFmpeg loudnorm filter. The loudnorm filter measures the integrated loudness (I), the true peak (TP), and the loudness range (LRA) of the full file. The allpass filter runs first. Thus the TP measurement shows the peak budget after the rotation. The measured values go to the next pass.
  2. Normalization Pass The same filter chain runs again with linear=true and the measured values from pass 1. The 200 Hz allpass filter runs here also. Thus the rendered output agrees with the measurement. This usually applies one precise linear gain. There is no compression and no change to the stereo image. If the loudness range of the mix is more than the configured LRA, loudnorm applies dynamic normalization for that file instead. The output is stereo (2 channels) by default. WaxOff upmixes a mono input to dual-mono at the start of the filter chain. Thus both passes measure and normalize the stereo signal. If you select mono delivery, WaxOff does not do the upmix and both passes run on the single native channel.
  3. Brick-Wall Limiter A 2× oversampled true-peak limiter runs after loudnorm. Its ceiling is your true-peak target. The limiter is a safety backstop. It catches the inter-sample peaks that the loudnorm linear-mode TP analysis did not find. On a well-mixed source the limiter does not operate. The output is a 24-bit WAV file at the target sample rate.
  4. MP3 Encoding Optional If Output is MP3 or Both, WaxOff encodes the normalized WAV file with libmp3lame at the selected CBR bitrate. A brick-wall limiter operates before the encoder. This limiter is 1 dB below your true-peak target. It gives a margin for the inter-sample peak overshoot that lossy decoders cause. Thus the decoded MP3 file stays below the same effective ceiling as the WAV file. WaxOff always encodes MP3 at 44.1 kHz. The sample rate setting has no effect on this. WaxOff always writes the WAV file first and makes the MP3 file from it.

While processing with no file selected, the waveform panel shows live phase labels: Analyzing loudness… → Normalizing… → Encoding MP3… Selecting a file shows its waveform and stats instead.

Why Two Passes?

EBU R128 loudness measurement requires the entire file to compute integrated loudness (gated measurement over the full duration). You can't know the correct gain until you've read every sample, so two passes are unavoidable for accurate normalization. WaxOff makes this transparent: drop the file, click Process, and both passes happen automatically.

File Stats

When you select a file in either mode, a stats strip shows below the waveform. The app computes the stats while the files load. Thus the strip fills in after a file joins the list, not when you select it. The analysis reads each file from start to end, because integrated loudness needs all the audio data. Thus a longer file takes more time. The app analyzes a large batch a few files at a time. After the app processes a file, the strip shows the info and the measurements of the output file. An OUTPUT badge marks this.

The strip has two rows with a divider between them. The file info is on top. The audio analysis is below.

File Info Row

FORMAT
The container format, such as WAV, MP3, or FLAC.
SR
The sample rate, such as 44.1 kHz or 48 kHz.
CH
The channel layout: Stereo or Mono.
BIT
The bit depth: 16-bit, 24-bit, or 32-bit. The app does not show this for a lossy format.
DUR
The duration in M:SS or H:MM:SS.
BR
The bit rate in Mbps or kbps. The app calculates it from the file size and the duration.

Audio Stats Row

RMS
The Root Mean Square level in dBFS. This is the average loudness of the full file.
PEAK
The sample peak level in dBFS. This is the highest sample value in all the channels. The colour is orange at −3 dBFS and above, and red at 0 dBFS.
ISP (est.)
The estimated inter-sample peak in dBFS, from 2× linear interpolation between samples. The app shows it only when the estimate is more than 0.1 dB above the sample peak. This value is a lower limit and not a full BS.1770 true-peak measurement. The real true peak can be higher. The "measured" line in the Console after processing gives the broadcast-accurate value. The colour code is the same as PEAK.
CREST
The crest factor (PEAK − RMS) in dB. It shows the dynamic range. A higher value means more headroom between the peaks and the average level.
LUFS
The integrated loudness to ITU-R BS.1770-4. This is the broadcast and streaming standard. The app computes it with K-weighting and two-stage gating: absolute −70 LUFS and relative −10 LU. For an unprocessed file the label is LUFS (src). This is the integrated loudness of the source before any processing.
FLOOR
The estimated noise floor in dBFS. This is the 10th percentile of the RMS values of the blocks. It represents the quietest sections of the file, such as room tone and background noise. The app shows it only when sufficient audio blocks are available. Refer to Noise Floor Warning below.
LUFS vs. RMS Both values measure loudness. LUFS is perceptually weighted and gated. Silence does not decrease the value. High-frequency content has a weight that agrees more closely with human hearing. To compare files for broadcast or streaming, use LUFS.
Noise Floor Warning In WaxOn the FLOOR value has a colour code. The colour is orange above −50 dBFS, where the noise floor can decrease the loudness accuracy. The colour is red above −40 dBFS, where the noise floor very probably changes the measurements. A file with a high estimated noise floor also shows a ⚠️ badge next to the filename in the file list. A high noise floor can increase the integrated loudness measurement. Loudness normalization then applies less gain than the speech content needs. When Loudness Norm is on, WaxOn applies RNNoise to the measurement pass to prevent this. RNNoise has no effect on the output signal. If the badge shows, turn on Loudness Norm so that the analysis runs with RNNoise. In WaxOff the value has no colour code and the badge does not show. A finished delivery mix can correctly contain continuous low-level content, such as a music bed or room tone under a mix, so the thresholds for raw speech do not apply.

Supported Formats

WAV, AIFF, AIF, AIFC, MP3, FLAC, M4A, CAF, AAC, MP4, MOV.

MP4 and MOV are video containers. The app extracts the audio track and processes it in the usual way. All processing uses FFmpeg. FFmpeg is included in the app. You do not install it separately. The app rejects an unsupported file type. A notice shows if the app skipped any of the files you added.

Tips & Workflow

The Full Podcast Workflow

  1. Record the host and the guest on separate tracks.
  2. Drag the two files into WaxOn. Click Process.
  3. Edit the audio in your DAW. Remove the noise. Add the music. Cut and arrange the material.
  4. Export your finished mix from the DAW.
  5. Drag the exported file into WaxOff. Click Process.
  6. Upload the WaxOff output file to your podcast host.

Checking Levels Before Processing

Select a file. Read the stats strip before you click Process. The LUFS value shows the loudness of the file. In WaxOn, a LUFS value much below your target means that normalization applies a large gain. This is correct for ingest, but you must know about it. In WaxOff, compare the input LUFS value with your target. The difference is the gain that WaxOff applies.

Reading the Noise Floor

The FLOOR stat estimates the background noise level. A value below −60 dBFS usually shows a clean recording. Between −60 and −50 dBFS you can possibly hear the noise, but it usually has no effect on the processing. Above −50 dBFS (orange) the noise floor can change the loudness measurements. Above −40 dBFS (red) it almost certainly changes the results. At these levels, turn Loudness Norm on. WaxOn then applies RNNoise to the measurement pass. For the best result, also use a dedicated noise-reduction tool such as iZotope RX on the source before WaxOn.

WaxOn: Loudnorm On or Off?

Turn Loudness Norm on for consistent batch ingest when you recorded the files at different gain levels. Loudness Norm makes sure that every file has the same integrated loudness before the limiter. Turn Loudness Norm off for a single file, or when you want to keep the original level relation between takes. Downward-only linear peak normalization then controls the ceiling only. There is no limiting.

WaxOff: Choosing a LUFS Target

−18 LUFS is a safe, conservative delivery target. The platforms do not use this level themselves. It is below the targets of the major platforms: Spotify uses −14 LUFS and Apple Podcasts uses −16 LUFS. Thus both platforms increase the level of your file by a small quantity and do not decrease it. −16 LUFS gives a louder result and stays in the usual platform limits. A level above −14 LUFS can cause clipping, and some platforms can reject the file. If you are not sure, use the Podcast Standard preset.

WaxOn: Mono vs. Stereo for Podcasts

Most podcast editing workflows use one mono track for each speaker. A mono track is easier to pan, to balance, and to process. Use Mono / Left for a standard single-mic recording on channel 1. If your interface records both microphones in one stereo file, set Channels to Stereo and process the file before you put it in your DAW.

Phase Rotation (WaxOn)

Keep Phase Rotation on unless you have a specific reason to turn it off. The 200 Hz allpass filter reduces the crest factor of a voice recording. Thus the limiter has more headroom. You cannot hear the effect on speech.
